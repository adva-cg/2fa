## Adding an account could stop working for good

This release fixes a bug that left some people unable to add any account at
all — not by scanning a QR code, not by typing the key — and it fixes a second
one that the search for the first turned up.

**What people saw.** Scanning a Google Authenticator export failed with
"Refusing to save 12 accounts over 22 already stored". Typing the key by hand
failed with "The account could not be saved. Please try again." Trying again
never helped.

**What had happened.** With sync on, the copy in your Google account can spell
the same key differently from the copy on this computer — lower case, or with
spaces. When the two were combined, those spellings were taken for new
accounts, and every account ended up on disk twice. The list still showed each
one once, so nothing looked wrong. But the extension refuses any save that
would leave fewer accounts on disk than are already there. That rule is what
stops a bad read from wiping everything. Here it saw "eleven you can see, plus
the one you are adding" against twenty-two stored, and refused every time.

**Your accounts were never at risk.** Every code kept working, and nothing was
deleted. After this update, adding works again with nothing for you to do: the
duplicates collapse the next time anything is saved. If you tried to import a
Google Authenticator export and it failed, scan it again. Accounts you already
have are skipped, not added twice.

## A deleted account could come back

Since 1.13.0 the app can stay open as a side panel or a floating window, and
every open copy reloads when your accounts change. Deleting an account with sync
on started one of those reloads before the deletion had been fully recorded, and
the reload fetched the account back from the sync copy. It looked like a delete
that did not work. Deletions are now recorded before anything else happens.

## Also in this release

- **Setting up a new computer no longer shrinks the sync copy.** If you added an
  account on a new computer before your other accounts had arrived from sync,
  the first sync could overwrite the copy in your Google account with just that
  one account. Your accounts stayed on the new computer, but the copy you rely
  on to set up the next one did not. Sync now always keeps everything.
- **Error messages are in your language.** Several screens used to show the raw
  English text of an internal error. They now say what happened in the language
  the app is set to, and never show an error's internals.
- **Accounts left out of an import are counted.** A Google Authenticator export
  can contain accounts this extension cannot use: counter-based (HOTP) ones, or
  damaged entries. They used to be dropped without a word, so "8 added" out of
  ten looked like the whole export. The message now says how many were left out.
- **A split export with one usable account still says "scan the next code".**
- **"Account added" only when something was.** Adding a key that is already in
  the list now says so, instead of reporting success with no new row.
- **Failed edits and deletes say so.** A failure used to leave the Save button
  looking like it did nothing, and the edit form now stays open with what you
  typed.
- **Importing a file with the same key twice** adds it once and counts it once.
  An account whose id is already taken gets a new one, so deleting it can never
  delete a different account too.
- **Two QR codes that were wrongly called invalid now scan:** a migration link
  written in capitals, and an account name containing a bare `%`.

## If you are coming from 1.13.1

1.13.2 never reached the Chrome Web Store, so this is the first time most
people get what it added: **Settings → Automatic copies**, which lists the daily
copies of your account list the extension has kept since 1.10.0, and lets you
put any of them back. The [1.13.2 notes](v1.13.2.md) explain it in full.

No permissions changed in this release. The store rollout follows separately, so
this version may be here before it reaches your browser.
